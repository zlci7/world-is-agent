## 1. 目标与边界

在同一 Agent 的持久历史中找回近期窗口外的原文细节，并按显式保留策略管理旧原文容量。检索与清理均由 Runtime 管理，Context 负责最终输入。

本阶段包含有界自动字面检索、中文查询、来源片段、Context 去重与预算、派生索引维护和可选原文清理。

本阶段不包含语义同义检索、embedding、外部搜索服务、模型主动 Memory Tool、Semantic 更正、共享记忆、后台反思 Agent、Adapter/proto 修改、动作恢复或完整存档分支管理。不以“检索未命中”证明某事从未发生。

8.2 在本阶段开发前已经独立交付 History 与 Summary；检索或清理失败不得破坏其历史连续性。

## 2. 数据来源与接口

### 2.1 数据职责

| 数据 | 职责 |
| --- | --- |
| `session_history` | 持久来源及原文可用性；继承 8.2 的 owner、稳定键、序号、指纹和时间 |
| `context_summaries` | 保留摘要、精确覆盖关系与累计时间来源 |
| 历史检索索引 | 从仍保留的原文派生，可以重建；不保存独立的认知结论 |

搜索内容来自 ContextFact.text、工具参数和实际结果中可直接读取的文本值。使用结构化 JSON 解析器提取文本，不对序列化 JSON、工具 schema、事件私有 payload 或完整模型 Request 做全文存储和索引。

索引中的每个片段保留来源 ID、片段定位、主体或原字段归属和原文；没有显式主体时显示来源性质，不猜测发言者。显示时从权威原文核对，不能把词项或匹配高亮重组为事实。

### 2.2 Runtime 内部接口

| 接口职责 | 输入 | 输出与保证 |
| --- | --- | --- |
| SearchHistory | owner、快照水位、当前通用时间、有界 query、扫描与分页限制 | 有序来源候选页、匹配信息及完整性诊断；不提前按最终注入数量截断 |
| ReadHistorySource | owner、已知来源 ID | 原文、已清理状态或不存在；不得跨 owner 暴露来源存在性 |
| RebuildHistoryIndex | owner 范围、有界游标 | 从可用原文重建派生索引，返回进度与状态 |
| PruneHistory | owner、当前现实时间、保留期、保护集合和批量限制 | 已清理来源及保留原因；清理与索引更新原子提交 |

这些接口不进入 proto，不注册为模型游戏工具。Store 不拼接 prompt，Context Build 不访问 SQLite。

## 3. 字面查询合同

### 3.1 查询来源

每个 Turn 在 8.2 历史快照准备后，从当前事件的通用 ContextFact.text 构造一次有界查询，与同一 owner、水位和时间上下文绑定。后续 step 复用结果，不为每次模型请求重新检索。

首版采用通用字符规则：连续中文文本切为相邻双字词项；连续拉丁字母与数字组成词项，字母统一小写；标点与空白作为边界。去重后按首次出现顺序取有界词项，不配置“我喜欢”等句式或业务主题词典。单个中文字符、纯标点或空输入不构成有效查询。

这是字面匹配，不理解同义词、指代或语义等价。“钓鱼”可以匹配包含“钓鱼”的来源，但不保证匹配只写“垂钓”的来源。数字与实体名按同一规则处理。

### 3.2 索引与排序

首版使用同一 SQLite 库中的普通倒排词项表，以 owner、词项、来源和片段定位建立索引；中文双字词项与拉丁/数字词项使用同一管线。无需增加分词模型或外部服务。FTS5 可作为后续内部索引替换，必须保持中文短词与来源一致性合同，不能以只通过英文 MATCH 验证代替。

读取先限制 owner 与快照，再按命中词项数降序、来源持久序号降序、片段定位稳定排序进行有界分页。最终数量限制在时间可见性过滤和近期原文片段去重之后执行；同一次查询在既定扫描上限内继续提供候选，不能让重复项提前占满名额。模型显示按来源顺序排列。匹配分数只表示字面覆盖，不称为语义置信度。

数据库 I/O 由 Agent 层完成，Context 只对准备好的有界候选执行纯选择。Store 分页数量与 `history_retrieval_limit` 分开，后者限制 Context 去重后的结果，不是候选预截断数量。

达到扫描上限、索引尚未覆盖全部快照或某页读取失败时，报告对应原因；不能把部分扫描结果称为全库最佳匹配。索引重建期间，已建立索引的范围可以返回部分结果，8.2 的摘要与尾部继续可用。

### 3.3 初始限制

下列为拟实现默认值，均受最终请求硬预算约束：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `history_retrieval_enabled` | true | 启用 Runtime 自动字面检索 |
| `history_query_max_chars` | 256 | 按 Unicode 字符计的查询输入上限 |
| `history_query_max_terms` | 32 | 去重后词项上限 |
| `history_search_scan_limit` | 512 | 一次查询最多检查的候选片段 |
| `history_retrieval_limit` | 5 | 时间过滤和近期去重后，Context 最多选择的来源片段 |
| `max_retrieved_history_tokens` | 1024 | 进入 Context 的检索片段总预算 |
| `retention_days` | 0 | 原文保留期；0 表示关闭清理 |

查询参数使用 SQL 绑定，不拼接用户文本。原文索引按完整历史单元处理，超出明确的索引安全容量时报告覆盖不完整，不能静默声称该来源已经可搜索。

## 4. Context 接入与诊断

```text
fixed owner/history snapshot + current ContextFact text
    -> bounded literal query
    -> index candidates + authoritative source verification
    -> time visibility
    -> deduplicate against recent original text, then apply final count limit
    -> Retrieved History projection
    -> Context budget and Renderer
    -> final model.Request
```

- 相同来源片段只注入一次。某个完整历史单元已在近期原文中时，去掉该单元对应检索片段；近期投影有裁剪时按实际片段覆盖去重。
- 摘要覆盖不等于保留全部细节。摘要已覆盖的旧来源仍可检索，其片段作为原文补充呈现；不能因来源已被摘要覆盖而屏蔽检索。
- 片段保留主体、来源时间、来源 ID、字段性质及裁剪标记。输出未包含的部分不推断为不存在。
- 检索内容作为历史数据，不能覆盖系统规则、工具权限或当前 Observation。原文中的指令不是 Runtime 指令。
- 检索段使用独立预算，并服从请求总预算；不能挤出当前必需事实与最新因果链。

至少区分以下诊断：无有效查询、无匹配、扫描不完整、索引未就绪、读取失败、时间隐藏、近期去重、预算未纳入、最终纳入、已知来源原文已清理。

普通搜索没有命中时，不报告“记忆已过期”。只有按 owner 校验后的已知来源引用，才能根据原文可用性报告已清理。

## 5. 索引一致性与迁移

目标 schema 为 `phase8_3_history_v1`，在已验收的 8.2 数据库上迁移。新增索引、原文可用性和维护进度的必要存储，不修改历史内容的含义或 Summary 覆盖集合。

- Schema、绑定身份和旧数据通过校验后才升级；DDL、metadata 与必要数据转换在同一事务中完成，失败回滚。
- 历史索引属于派生数据，旧原文采用有界分页重建。重建完成前记录覆盖范围，不能标记完整可检索。
- 新历史的索引与原文处于同一提交边界；索引维护失败时事务整体回滚，并保持 8.2 写入失败不影响 Turn 的行为。
- 索引可从可用原文重建。重复构建幂等；删除或重建索引不会改变原文或摘要。
- 已清理的原文不参加重建，原始指纹或残留词项不能被解释成可读原文。
- 旧版程序读取升级库不作兼容保证；不通过自动 reset 解决 schema 不匹配。

## 6. 原文留存与清理

### 6.1 默认与年龄

`retention_days = 0` 默认完整保留原文。启用时由部署配置设置正整数天数；年龄依据原始现实写入时间，不按 GameTime，不因迁移、重建索引或等价重试刷新年龄。

清理是原文留存策略，不是数据库总大小硬上限。摘要、来源指纹、时间和必要覆盖元数据继续保留，数据库文件也不保证在删除后立即缩小。

### 6.2 删除资格

一个完整历史单元只有同时满足以下条件才可以清理：

1. 现实写入年龄严格超过配置保留期。
2. 被成功提交且仍保留的摘要完整覆盖，覆盖关系及时间来源可以核对。
3. 不属于当前有效摘要以外尚需保留的近期原文尾部；尾部保护沿用 8.2 的 token 选择，至少保护最新一个完整单元。
4. 不属于当前 Turn、摘要生成或其它正在读取的快照保护集合。

未覆盖的原文始终保留。清理不为了释放空间而调用 LLM，也不强行删除没有摘要的旧内容。回档或预算导致近期保护范围暂时无法证明时，保守保留对应原文。

### 6.3 维护时机与原子性

清理在 Runtime 明确的维护入口执行。首版在一次 Turn 的持久写入尝试结束后，向现有 entity lane 投递最多一个可合并的有界维护任务，排在已等待的玩家 Turn 后；没有独立定时线程或模型 Agent。空闲且没有新 Turn 时不承诺按墙钟准时清理。

每次维护只处理一个有界批次，检查取消并限制锁等待，事务结束后释放 lane。候选筛选可以在事务外完成，真正清理时须在事务内重新校验资格。多实例共享写入同一世界库不列为本阶段保证。

清理原文内容及对应检索片段和词项，保留来源头信息、稳定键、内容指纹、时间、摘要覆盖和清理状态。保留的头信息支持重试判定、来源已清理诊断和未来时间检查，不是可还原的原文。

关联的 legacy Recent 若仍保存同一来源原文，也纳入同一清理事务；保留幂等凭据和迁移映射，不能通过 legacy 读取路径重新注入已清理内容。任一步失败，原文、legacy 副本、索引和可用性标记整体回滚。

等价重试已清理来源时返回既有结果，不重新插入原文；不同内容仍拒绝冲突。手动 VACUUM 属于运维操作，不进入玩家交互热路径，不由本阶段自动执行。

### 6.4 删除后的能力

已清理原文不能再精确检索，不能用于重新生成该范围的早期摘要。摘要可见性仍检查累计来源时间，不能因原文已删除而放过未来内容。

回档到已清理范围时，只能使用仍有效的摘要和剩余原文；没有合格来源时明确降级。有限原文保留期与任意旧存档精确恢复不能同时保证。

## 7. 修改范围与里程碑

修改范围为 Memory 的查询、派生索引与维护，Agent 的 turn-scoped 接线与维护调度，Context 的 Retrieved 投影、去重和预算，以及配置和测试。8.2 的来源采集、SummaryGenerator 与当前 Turn Transcript 不扩大职责。

| Milestone | 交付 | 通过标准 |
| --- | --- | --- |
| M1 检索与中文样例 | schema、字面词项、查询、索引重建、时间过滤 | 中文双字词、标点、数字和实体名可验证；作用域不串线；索引可重建，部分扫描可诊断 |
| M2 Context 接入 | 每 Turn 一次查询、来源片段、去重与独立预算 | 近期窗口外、摘要未保留的细节进入最终请求；当前因果链与输入硬预算稳定 |
| M3 留存维护 | 默认关闭、年龄与覆盖保护、维护入口、原子清理 | 未覆盖原文保留；符合条件原文清理；在用数据受保护；失败回滚；旧索引与 legacy 不复活原文 |
| M4 重启与回档验收 | 真实进程、中文交互、删除后能力和性能 | 重启后检索正确；回档隐藏未来来源与摘要；记录检索耗时、维护延迟、输入规模及磁盘变化 |

各里程碑先写失败测试再实现。代码复审与修正完成后交项目负责人评审，不与 8.2 混合开发验收。

## 8. 验收样例

### 8.1 检索证据

1. 在 FakeGame 的 `agent-1/world-a` 保存玩家原话“钓鱼时记下的数字是 7319”，随后加入足够历史使其离开近期尾部。
2. Fake SummaryGenerator 生成不含 7319 的摘要，证明不能仅依赖摘要作答。
3. 当前 ContextFact 输入“钓鱼时那个数字是多少？”，自动 query 必须命中旧来源，最终 RecordingProvider Request 包含原文、主体和来源 ID。
4. 改为中文短词“钓鱼”、数字“7319”、夹标点文本、大小写拉丁实体名，验证词项生成与检索；纯标点与单中文字返回无有效查询。
5. `agent-2`、其它 world/game 不返回该来源。让未来候选超过一页，证明时间过滤不会被最终数量 limit 截断；达到扫描上限则报告不完整。
6. 删除派生索引后重建，来源与最终可用内容保持；重复重建无副本，部分索引不假报完整。
7. 当前近期原文已包含该片段时只注入一次；摘要覆盖本身不阻止省略细节的原文召回。
8. 前五个命中均与近期原文重复，第六个是窗口外来源且位于扫描预算内；去重后第六个仍可进入最终请求，不因候选预截断丢失。

### 8.2 清理证据

- 默认 `retention_days = 0`，任意年龄均不清理。
- 使用注入时钟构造未到期、恰好到期和超过期限数据；GameTime 回退、迁移和重试不改变原始现实年龄。
- 超期但未覆盖、只部分覆盖、处于近期尾部或在用快照中的单元均保留；只有完整符合条件者可清理。
- 注入原文或索引删除失败，检查整笔回滚，包括 legacy 副本与原文可用性标记。
- 清理后按已知 ID 得到原文已清理，普通搜索仅得到无匹配；重建索引和等价重试均不复活原文。
- 原文清理后，摘要仍因累计未来来源被隐藏；存在回档后晚写入的较早 GameTime 时，不能用最大序号跳过检查。
- 关闭清理后保留余下数据，不声称恢复已删除原文。维护任务不触发模型调用，不持有无限事务。

### 8.3 实机与性能

同一存档与 NPC 使用中文对话，记录原文写入、离开尾部、后续自动检索、最终输入与真实 Runtime 重启后的证据。清理验收使用单独测试世界或数据库副本，不删除玩家正在使用的历史。

记录配置、world/entity、来源 ID、快照、命中与最终纳入数量、查询耗时、维护等待、最终输入 token、模型交互延迟及原文/索引大小。性能结论区分 SQLite 查询、维护和模型思考耗时，不用 NPC 一句“记得”替代数据链路证据。
