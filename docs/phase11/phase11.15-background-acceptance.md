## 参数纠错与任务状态

使用通用 fake capability、真实 SQLite Task Service 和当前 Loop 验证：

| 场景 | 当前结果 |
| --- | --- |
| 参数错误后正确取消任务 | 第一次调用不写任务；原始参数与工具错误进入下一步；修正后只发生一次有效更新 |
| 连续两次参数错误 | 第二次后明确失败，任务保持原状态，无游戏动作提交 |
| 纠错期间任务版本变化 | 下一步读取当前版本，修正作用于当前快照，无旧版本重放 |
| 纠错期间任务已取消 | 已失效的更新工具被拒绝，任务无额外修改，错误调用参数从持久化历史中移除 |
| 环境能力与任务工具同名 | 历史处理按已准入的实际 executor 识别，保留环境能力原有记录语义 |

任务工具归属与每步的准入状态分别维护。当前回合保留模型纠错所需的调用内容，终态历史继续移除任务工具参数。当前开发上下文已完成内部 CR；本结论不包含独立上下文审查。

## 开发版进程与任务 API

当前开发二进制启动四个独立测试进程，九项检查通过：

| 场景 | 当前结果 |
| --- | --- |
| 空配置启动 | 保持需要配置状态；选择游戏后仍要求模型配置 |
| 已持久化任务 | 正确读取两条活动任务、一条取消任务及任务详情 |
| 离线世界 | 任务存在时仍显示 `waiting_for_world`，不推断真实世界已 Ready |
| 进程终止后重启 | 游戏与 fake 模型配置保留；任务 ID、状态与详情保持一致；实例 ID 更新 |
| 旧实例查询 | 返回 HTTP 409 |
| 精确恢复指定保存点 | 活动列表由两条恢复为保存点内的一条；取消任务保留；保存点之后创建的任务详情返回 HTTP 404 |
| 游戏切换与重启 | 切换到 RimWorld 后预约未启用；重启保留游戏选择；切回 Stardew 后保持已恢复工作集 |
| 网页资源 | 实际进程提供 `zh-CN` 页面与中文预约任务资源 |

保存点由测试工具通过正式 Task Service 创建和恢复；本项证明 Task 数据与实际进程 HTTP 视图一致，不代表游戏保存读档通过。四个测试进程均已退出。

- 普通异步 Action 的等待仍为进程内状态；后台恢复测试不构成无人值守长期成功保证。
