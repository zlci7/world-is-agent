## 真实模型与体验

当前本地模型配置为 DeepSeek。通过 Runtime 自身的配置与凭据解析链路运行两条目标场景，均返回 HTTP 401，未产生角色回答。该结果属于模型鉴权阻断，不是角色内容通过或失败的证据。凭据没有写入场景、日志或文档。

待有效模型配置后执行：

1. 每名普通角色的适用基础场景：初识、熟悉、人物关系、季节地点、设施前后、事件已见或未见、错误暗示、未知与回档。
2. 24 条目标场景：检查澄清、建议、拒绝与不提案，不用模型自评代替内容判断。
3. 按角色类型选代表连续约 20 轮，检查重复介绍、语气漂移、事实优先与历史承接。

真实模型对合成观察的回答与真实游戏交互分别记录。前者通过不能代替后者。

## 实机验收步骤

使用测试存档副本，安装当前源码构建的 Adapter，并让 Runtime 使用本轮 definition。已有数据根保留现有文件，需先备份再按官方文件清单更新；保持模型配置、自定义文件、Memory 和 Task。

| 场景 | 操作 | 预期与失败时行为 |
| --- | --- | --- |
| 普通聊天 | 空手点击无原生提交的 NPC | 进入中文 AI 对话；Runtime 不可用时保留原生交互 |
| 送礼 | 手持无匹配交付任务的礼物互动 | 按原版处理接受或拒收，不进入 AI 等待，也不多扣物品 |
| 原生交付 | 接任务后手持正确、错误和数量不足的物品分别互动 | 原版校验与处理；只有真实完成才能承接成功 |
| 钓鱼计数 | 接取 Willy 原生钓鱼任务，钓前、未够、够数分别询问 | 读取当前任务与真实计数，不以口头自报替代 |
| 钓鱼提交 | 达到数量后空手与 Willy 互动 | 放行原版报告；计数达标不提前当作任务完成或领奖 |
| 后续承接 | 完成后再次聊天，再重启 Runtime | 当前游戏结果可以供 Willy 承接，无重复交付或发奖 |
| 原生状态移除 | 分别取消、过期、领奖移除 | 未观察到完成时为 unavailable；不从消失推断原因 |
| 保存加载 | 未完成和完成状态分别保存、退出、重新加载 | 关联跟随当前游戏存档，重新读取事实 |
| 回档 | 完成后回到任务仍未完成的存档 | 当前原生状态优先，不沿用未来的完成结论 |
| 关系与设施 | 恋爱／室友变化、修复安排当日与生效次日分别询问 | 读取真实身份和设施状态；未知时不猜测 |
| Dwarf | 未学会与已学会语言分别互动 | 未学会时沿用原生交互；已学会后才进入可用 AI 入口 |

预约另按 [11.1 恢复矩阵](phase11.1-acceptance.md) 验收。普通聊天 Memory 的废弃分支隔离限制仍存在；原生任务 metadata 不构成对通用 Memory 回档问题的修复。

## 玩家价值门槛

至少五次真实目标协作，记录目标、当前进度、建议、是否采用、实际行动和反馈。至少三次采用且至少三次能说明具体帮助，同时没有已知进度错误、虚构修改规则或假完成，才评估新增一种受限委托。当前没有这组试玩证据。
