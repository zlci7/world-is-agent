# World Is Agent Phase11.2 云端 Runtime 托管与上线技术方案

日期：2026-10-17（Asia/Shanghai）

状态：实施方案，托管服务、远程 Mod 接入、账号与云端数据功能尚未实现或验收。

代码基线：Runtime `c14a75c`，官方 Adapter `ebc295485d6655a6bb5dab830633ca2aa6a69e41`。依赖条件：[Phase11.1 预约任务恢复可靠性与 Web 状态展示](phase11.1-task-recovery-and-console.md) 完成并通过验收后，作为托管功能基线。

## 1. 产品目标与首版范围

玩家在本地安装 WIA Mod、填写个人 WIA Key、启动游戏并加载存档后即可游玩。Runtime、模型调用、角色历史、预约任务和账号偏好运行或保存在服务器。玩家电脑承担游戏模拟与动作执行。

首版为小规模邀请制服务：

- 支持 Windows 上的 Stardew Valley；按文档安装 SMAPI 与匹配版本 WIA Mod，解压到 Mods 目录。
- 每账号拥有独立 Runtime 实例与持久数据目录，同一时刻连接一个设备上的一个游戏世界。
- 平台统一提供一个经验证的模型配置，玩家使用 WIA Key 连接，无需启动本地 Runtime 或提供模型 API Key。
- 提供账号登录、安装指引、连接密钥、连接状态、Phase11.1 任务视图、近期回合、有限的显式偏好设置与剩余额度。
- 普通网页直接显示账号已配置并连接的游戏。首版游戏固定为 Stardew，不提供跨游戏运行切换入口；主题跟随已确认游戏直接更新。
- 本地模式保持可独立运行，托管模式具有单独的入口、凭证与配置。

本方案不包含付费订阅、支付、公开自助注册、任意模型接入、用户自定义上游地址、多地域调度、多节点共享 SQLite、多设备同时控制同一账号、多人同存档写入、游戏离线模拟或自主目标生成。RimWorld 的远程接入另行验收。

## 2. 与 Phase11.1 的职责划分

| 内容 | Phase11.1 提供 | Phase11.2 提供 |
| --- | --- | --- |
| Task | 保存、读档、重启恢复和真实结果；只读 DTO / API | 公网接入下的恢复验证、账号范围封装与托管展示 |
| 数据身份 | 游戏、世界、角色、run、generation 与实例身份 | 鉴权账号、设备凭证、独立 worker 与数据目录绑定 |
| 网页 | 中文像素布局、任务组件、状态映射、响应门控 | 账号入口、接入指引、密钥、额度与托管权限 |
| 网络与运维 | 本地监听、本地会话、便携包 | 公网 TLS、鉴权、流路由、Linux worker、监控、备份与上线 |
| 模型与偏好 | 本地模型配置和已有角色历史 | 平台模型代理、账号额度、云端显式玩家偏好 |

Phase11.1 不新增账号字段、WIA Key、服务器入口、云端数据库或额度依赖。Phase11.2 复用其查询、恢复与组件契约，账号边界由外层鉴权和独立实例建立。

本地网页中的模型密钥、接口地址和配置路径属于本地模式。托管网页只提供已脱敏的模型摘要；模型凭据、上游地址和 worker 配置由平台管理。

## 3. 当前实现与上线缺口

| 当前事实 | 上线增量 |
| --- | --- |
| Adapter 主动建立 gRPC 双向流 | 公网 TLS、连接凭证、认证后的流路由与兼容性检查 |
| Stardew 的 RuntimeAddress 可配置，尚无账号认证 | 增加托管连接设置、WIA Key 和可理解的错误状态 |
| RimWorld 使用固定本地地址与明文 ChannelCredentials | 保留本地使用，首版不作为托管支持对象 |
| 一个 Runtime 进程只发布一个游戏实例 | 按账号分配独立 worker，所有权与生命周期由托管服务管理 |
| Memory 按游戏与世界划分 SQLite，Task 位于数据根 | 每账号绑定独立持久根目录，不共享不同账号的数据库 |
| HTTP 只接受回环地址、Host 与本地网页会话 | 新增账号服务与私有 worker 管理接口，保留本地 HTTP 规则 |
| Task 恢复依赖真实存档 checkpoint 与游戏证据 | 公网断线、服务重启、网关重启和备份恢复的独立验收 |

`AgentDefinition.Preferences` 是角色设定，不是账号玩家偏好。账号偏好拥有独立来源，不能通过改写 NPC definitions 保存玩家信息。

## 4. 部署与职责

首版采用单台 Linux 服务器、一个托管控制进程与每账号一个独立 Runtime 容器。容器与持久卷按服务端账号分配，镜像版本固定。

```text
玩家电脑
  Stardew + SMAPI + WIA Mod
        │ 主动建立 TLS gRPC 双向流
        ▼
公网入口（HTTP/2、证书、连接与消息上限）
        ▼
wia-hosted
  ├─ 账号 / 网页会话 / WIA Key
  ├─ 接入鉴权 / 版本检查 / 长流路由
  ├─ worker 管理 / 单账号连接所有权
  ├─ 账号 API / 偏好 / 额度与用量
  └─ 私有模型代理 ──► 平台配置的模型服务
        │ 固定路由到账号 worker
        ▼
账号 Runtime 容器
  ├─ Runtime Core、Game Profile、Task、Memory
  ├─ 私有管理接口
  └─ 独立持久卷：配置、Memory、Task、checkpoint、Trace

玩家浏览器 ── HTTPS / 账号会话 ──► wia-hosted ──► 自己的 worker
```

- 公网仅暴露托管网站与接入服务。worker 的 gRPC、管理接口与模型代理位于私有网络，不发布公网端口。
- 长流在整个连接生命周期内固定到一个账号 worker；部署和重启通过断开、重新鉴权和恢复建立新流，不在同一条流中途更换后端。
- 一账号同一时刻只有一个持久卷写入者。容器退出并确认进程释放资源后才能启动替代实例；所有权不明时拒绝第二个写入者。
- 不同 worker 挂载各自持久卷，不挂载其它账号数据、宿主根目录或容器管理 socket。
- Core 继续保持 game-agnostic。账号、容器调度、额度和公网认证不进入 Task 调度、游戏事件解释或路径规划逻辑。
- 初期实例由单一控制进程管理；托管控制进程采用单写入者部署锁。首版不实现多主调度或跨节点迁移。

## 5. 身份、凭证与权限

### 5.1 三类身份

| 身份 | 来源 | 用途 |
| --- | --- | --- |
| `account_id` | 账号服务生成的稳定不透明 ID | 数据所有者与额度归属；更换密钥保持不变 |
| `device_id` | Mod 安装时生成并保存在本机 | 识别安装与重连；本身不提供授权 |
| `worker_id / worker_generation` | 托管控制进程分配 | 私有路由与进程所有权，阻断退役实例 |

游戏的 `game_id / world_id / world_run_id / entity_id` 延续现有协议。客户端声明的世界和角色不授予账号权限；所有消息的账号归属由认证连接固定。

### 5.2 邀请制账号与网页登录

- 运维通过私有管理命令创建有期限的一次性邀请，玩家凭邀请创建账号和密码；不依赖首版邮件或支付系统。
- 邀请兑换、登录和密码验证有按账号与来源限制的速率和并发预算。密码以 Argon2id 加盐哈希保存，参数经服务器基准验证后固定在发布配置中。
- 登录成功生成随机网页会话，服务端保存其验证值；Cookie 使用 Secure、HttpOnly 和 SameSite。状态修改同时检查合法 Origin 与 CSRF 凭证。
- 网页会话、Mod 连接 Key 与 worker 内部凭证分别管理。Mod Key 不能登录网站或调用账号管理接口。
- 退出或禁用账号撤销对应网页会话。内测密码恢复由私有管理流程完成，并记录操作审计。

### 5.3 WIA Key

- 登录网页后创建设备连接密钥，明文只返回一次。密钥包含可公开的 key ID 与至少 256 位随机秘密，服务端仅保存带服务端秘密的验证摘要。
- Key 绑定账号、用途、有效期、状态与设备绑定。首次成功建立支持版本的连接时绑定该安装的 `device_id`；更换设备由网页重新发放 Key。
- Mod 通过 gRPC 调用 metadata 的 `authorization: Bearer …` 提交凭证，使用 TLS 验证正式服务域名与证书。Key 不进入 Hello、Observation、游戏事件、模型上下文或 URL。
- 网页可查看密钥标识、状态、最近使用时间，创建替代 Key 或撤销 Key；不提供读取既有明文的接口。
- 撤销、到期或账号禁用后，拒绝新连接，并主动终止对应长流；已在执行的游戏动作按断线清理规则处理。
- 网关重启后，现有流全部重建并重新鉴权。撤销通知和定期有效性复核共同覆盖长连接，失去凭证状态来源时关闭准入。
- 密钥轮换不移动或删除记忆、预约与世界身份。

### 5.4 请求归属

公共网页接口使用 `/api/me/...`。服务器从会话确定账号，不接受请求体、路径、query 或自定义 header 指定另一个账号、数据路径、worker 地址或模型上游。

网关在转发之前剥离客户端自带的内部身份 header，由服务器重新建立私有调用凭证。游标和世界 ID 只是查询定位，不能改变账号路由。错误响应不披露其它账号是否存在。

## 6. worker 与连接所有权

### 6.1 worker 生命周期

```text
stopped → starting → running → draining → stopped
                    └─ 故障 → failed → 经所有权确认后重新启动
```

`running` 仅表示进程可接受管理请求；Runtime Ready、Adapter 连接和世界 Ready 分别读取。网站展示这些状态，不以容器存活推断游戏可玩。

- 创建 worker 前完成账号资格、并发容量、数据目录和游戏配置检查。
- 对同一账号加单一分配锁，绑定固定持久卷并产生新 worker generation；网关只使用当前发布的分配快照。
- worker 启动时显式设置数据根、已验证 Game Profile、托管模式与内部监听地址，不打开浏览器，不生成或打印本地会话交接链接。
- 仅发布通过私有身份校验、版本检查和 Runtime 状态读取的实例。实例失败保留数据与错误，不能用空目录启动来伪装恢复成功。
- 退出时先停止新回合与新准入，取消或排空旧回合，执行现有 Task 关闭及控制权清理，确认退出后再释放卷所有权。
- 空闲实例可以在显式解绑世界并完成排空后停止；再次连接使用同一持久卷。首版不以负载原因迁移仍在执行的账号。

### 6.2 一个账号、一个设备、一个世界

- 鉴权和 Hello 校验通过后，建立暂未绑定世界的连接；只有有效 WorldBinding 才能获得账号活动世界资格。
- 同一设备、同一世界的断线重连通过新的连接代次替换失效流，旧流不得继续提交事件或结果；同时保持 Runtime 原有 run、generation 和 world ownership 检查。
- 不同设备或不同世界在现有活动世界仍有效时返回 `account_in_use`，不自动抢占。客户端提示先退出原存档或断开原设备。
- 返回标题、切换存档或退出时按现有生命周期关闭旧绑定；新世界获得资格前先确认旧世界已失去执行权。
- 存档副本即使声明相同 world ID，也不能跨账号取得数据。首版不承诺自动识别同账号复制存档形成的独立时间线。

worker 进程所有权与游戏世界所有权分别判断。网络心跳或租约计时器不能替代对旧进程退出、世界绑定和真实执行证据的确认。

## 7. Mod 远程接入

### 7.1 配置与玩家操作

在 Stardew Adapter 增加明确的连接模式与托管设置：本地模式保留既有 RuntimeAddress；托管模式使用发行包附带的正式服务地址、WIA Key 与安装标识。发行包不包含共享密钥。

- 玩家只需填写 WIA Key，正式域名随版本提供；本地模式和开发地址入口供现有用户继续使用。
- 提供游戏内连接设置和状态入口。输入密钥使用遮盖显示，保存后不在日志和错误提示中回显。
- 安装说明明确 SMAPI、游戏与 Adapter 支持版本，文件放入 Mods 目录，不覆盖游戏原始程序或玩家存档。
- 默认服务不可用时保留游戏原生交互与日程；连接错误不导致 Mod 加载失败或游戏主线程阻塞。

| 状态 / code | 中文提示与行为 |
| --- | --- |
| `connecting` | 正在连接 WIA 服务；不阻止原生游戏操作 |
| `unauthenticated` / `key_revoked` | 密钥无效或已撤销，请在连接设置中更新；停止频繁自动重试 |
| `unsupported_adapter` | 当前 Mod 版本需要更新；显示匹配版本入口 |
| `account_in_use` | 账号已连接其它设备或存档；不抢占已有世界 |
| `service_busy` / `quota_exceeded` | 服务繁忙或额度不足；保留存档和记忆，不建立无界重试队列 |
| `waiting_for_world` | 服务已连接，请加载存档；不宣称角色已可执行任务 |
| `ready` | 当前世界已确认；允许现有事件与能力链路 |

### 7.2 传输、兼容与恢复

- 复用现有 gRPC 双向消息契约，认证与托管路由位于传输边界。首版不为账号身份修改游戏私有 Observation 或 ActionRequest。
- 首条消息须为合法 Hello，在有界时间内检查协议与 Adapter 版本、game allowlist；失败不进入游戏事件处理。
- HTTP/2 入口配置支持双向长流，验证代理空闲超时、keepalive、消息大小、发送背压和连接数上限；不能套用普通短 HTTP 请求的总时长限制。
- 重连采用有上限且带抖动的退避，凭证或版本错误等待玩家处理，网络错误可以自动恢复。
- 断线不把已发送动作重新当作未执行动作。按 Task operation、真实进展与 checkpoint 协调；普通 Action 的内存 continuation 不跨 worker 进程恢复。
- Observe、Action 和保存准备的截止时间分别验证。云端延迟不能通过无限等待或统一放大全部超时处理。
- 密钥、内部地址、模型凭证、完整存档与本机路径不进入模型上下文。上报内容继续采用现有窄 Observation 与受约束事实。

## 8. 云端数据与玩家偏好

### 8.1 存储归属

| 数据 | 位置与范围 |
| --- | --- |
| 账号、邀请、网页会话、Key 验证值、worker 分配、额度账本、显式偏好 | 托管控制进程的持久管理库，所有记录具有服务端 account_id |
| NPC 历史、摘要、检索、Task、工作集与 checkpoint | 账号 worker 的独立持久卷，继续按游戏、世界、角色及当前 Task 语义组织 |
| 游戏存档、游戏运行状态、动作执行与存档内 checkpoint 引用 | 玩家电脑，由游戏与 Adapter 负责 |
| 模型上游凭据 | 服务端受管秘密，仅模型代理读取 |
| WIA Key | 玩家电脑的 Mod 设置；服务端只保存验证值 |

账号目录由服务端稳定 ID 映射，不能由用户名、Key、world ID 或客户端路径拼接。容器替换保持挂载同一目录；密钥重置保持同一账号。现有 SQLite 不放在容器可丢弃层，也不由不同账号共用。

未包含 WIA checkpoint 的现有游戏存档，按现有首次绑定规则建立云端工作集，不要求玩家重新开始游戏。首版不自动上传或迁移玩家已有的本地 Runtime 历史；包含既有 WIA 引用的存档仍按精确 checkpoint 规则校验，服务端缺失对应快照时报告恢复受阻并给出人工处理指引，不静默清除引用。

### 8.2 显式玩家偏好

- 首版仅提供玩家明确设置的交流语言、称呼和交流风格；字段有长度、数量和总载荷限制。
- 偏好具有版本和更新时间，提供查看、修改与恢复默认；并发编辑通过版本条件避免覆盖。
- 账号偏好跨该账号游戏世界复用；NPC 经历、关系、预约和任务结果维持游戏世界范围。
- 托管层将已验证的偏好版本投影为 worker 的通用 PlayerPreferences 输入。Runtime 只读取这份上下文，不查询账号、Key 或计费库。
- 偏好作为玩家提供的有限上下文，不修改 system policy、Capability metadata、预算、协议、NPC definitions 或工具执行约束。
- 首版不从所有历史自动生成全局画像，不建立完整记忆浏览与编辑平台。清理账号数据通过受控账号管理流程处理。

### 8.3 生命周期与备份

- 账号正常使用期间保留权威 Memory、Task 与其可恢复 checkpoint；日志和 Trace 单独执行容量及保留期限配置。
- 首版一致备份采用账号维护窗口：停止新准入和新回合，完成排空并关闭 worker，备份完整账号卷、偏好版本和绑定清单，再从同一卷启动。备份过程不生成假的游戏保存或 checkpoint。
- 管理库采用一致性数据库备份，账号卷与管理库备份清单包含版本、account ID、worker 分配、时间与校验值。活跃 SQLite 不以单独复制主 db 文件的方式备份。
- 恢复到隔离验证目录，校验数据库、版本和绑定后再切换账号卷。恢复旧备份后，若玩家存档引用的 checkpoint 不存在，进入明确的恢复受阻状态，不选择最近快照替代。
- 数据删除在账号停用并撤销凭证、停止 worker 后执行，只定位服务端登记的账号目录；备份副本按已公布的生命周期到期清理。
- 部署前确定备份频率、备份保留、恢复目标和停用数据保留期限；网页与安装文档明确这些值及云端传输范围。

游戏关闭后，云端记录继续保存；游戏时间和游戏内动作由本地运行推动。云端不模拟离线世界，不在游戏离线时补造赴约成功。

## 9. 账号网页与 API

### 9.1 页面

沿用 Phase11.1 已确认的中文像素视觉、透明度、对齐和任务组件。

| 页面 / 区域 | 托管行为 |
| --- | --- |
| 登录与安装指引 | 邀请兑换、登录、匹配 Mod 下载、填写 Key、加载存档的步骤 |
| 运行概览 | 当前游戏、设备与存档连接、Runtime 状态、任务摘要、近期回合与剩余额度 |
| 预约任务 | 复用只读列表和详情；只读取账号 worker 的当前工作集 |
| 连接设置 | 创建或撤销设备 Key，查看状态、最近连接和支持版本 |
| 玩家偏好 | 有限字段的查看、修改、恢复默认 |

- 首版不提供跨游戏切换、玩家填写模型 API Key、模型上游 URL 或 worker 管理参数。
- 背景直接取已接纳状态中的当前游戏，未连接时保留该账号已配置游戏的主题，并明确显示连接状态；无有效游戏身份时使用中性主题。
- 登录、创建 Key、保存偏好等操作使用按钮忙碌态与就近反馈，无独立转场对话框或人为等待。
- 退出或更换账号时立即取消请求并清空任务、详情、计数、偏好和设备内容。托管页面的响应门控在 Phase11.1 范围外再绑定账号会话与 worker generation。
- 公共 DTO 不返回服务器路径、内部端口、上游地址、prompt、原始记录或完整 Trace；运行记录继续只读、有界和脱敏。

### 9.2 公共接口

以下为拟定 HTTP 契约，均属于 Phase11.2；修改接口沿用 Cookie / Origin / CSRF 检查并设置 `Cache-Control: no-store`。

| 接口 | 用途 |
| --- | --- |
| `POST /api/invitations/redeem` | 邀请兑换并创建账号 |
| `POST /api/session`、`DELETE /api/session` | 登录与退出 |
| `GET /api/me` | 脱敏账号信息与服务资格 |
| `GET /api/me/status` | worker、Runtime、Adapter 与世界分别投影的状态 |
| `GET /api/me/keys`、`POST /api/me/keys` | Key 元信息、一次性明文创建 |
| `DELETE /api/me/keys/{key_id}` | 撤销自己的设备连接 Key |
| `GET /api/me/preferences`、`PUT /api/me/preferences` | 读取和按版本写入有限偏好 |
| `GET /api/me/usage` | 当前额度周期、已使用、待结算与剩余额度 |
| `GET /api/me/task-worlds`、`GET /api/me/tasks`、`GET /api/me/tasks/detail` | 账号路由后复用 Phase11.1 查询语义 |
| `GET /api/me/turns` | 当前账号、当前游戏的有界近期回合 |

账号 API 固定路由到当前 worker 分配，底层继续验证 `instance_id / game_id / world_id`。底层游标不授予权限，也不改变 worker 选择；跨账号、退役实例和旧会话响应均需拒绝或丢弃。

### 9.3 私有 worker 管理

新增受内部服务凭证保护的管理入口，负责状态、只读查询、平台配置和偏好投影。服务凭证绑定 worker ID、generation、调用用途与有效期。

此入口独立于现有 loopback HTTP 服务，托管模式不通过取消 Host 检查或复用浏览器交接 Cookie 暴露现有管理面。公共 API 只调用白名单操作，不做任意路径反向代理。

## 10. 平台模型与额度

模型代理属于托管层。worker 使用平台生成且绑定账号与实例的内部模型凭证，调用私有模型入口；真实上游 Key 由模型代理持有。

- 首版固定一个经工具调用验证的 Provider / 模型组合，保留现有模型请求、工具参数、响应与取消语义，不提供任意兼容服务透传。
- 模型调用前原子预留额度并检查账号状态、账号并发与全局容量；达到上限返回有类型的受限结果，不进入无界队列。
- 单次输入、最大输出、工具回合数、账号每日额度、账号模型并发和全局并发必须有显式配置。缺少预算配置不开放托管准入。
- 额度采用明确的计量周期和时区。页面展示周期起止、已结算与待结算，不把每日额度包装成未经核算的费用承诺。
- 预留量使用已选模型的确定性计量或保守上界，包含允许的最大输出。收到可靠 usage 后结算；超时或 usage 不明保留不确定预留，不全部退还后无限重试。
- 重复请求按平台请求 ID 幂等处理。已提交上游但结果未知的调用不透明重放，配额账本重启后仍成立。
- 账号被限流、欠缺额度或上游不可用时，停止新增模型工作；已发送游戏动作继续按真实结果收敛，不能将服务错误转换为任务成功。
- 额度错误、等待和解除限制均有中文提示，游戏本身保持正常运行。

## 11. 公网恢复与服务故障

| 场景 | 必须成立的行为 |
| --- | --- |
| 网络短断、Wi-Fi 切换 | 自动退避重连、重新鉴权与世界绑定；旧流失去权威，不重复创建任务 |
| 动作已执行但结果回包丢失 | 以既有 operation 和环境事实协调；无法确认时暂停，不盲目重发 |
| worker 异常退出 | 确认旧写入者退出，挂载同一卷启动；恢复 working head / 精确 checkpoint；普通 Action continuation 不续接 |
| 网关或托管控制进程重启 | 重建账号到 worker 的权威路由与额度状态；长流重新认证；不因注册信息缺失创建第二个写入者 |
| 玩家保存时断网 | 复用有界保存准备与未确认引用规则，游戏实际保存不无限等待；重新在线后明确提示恢复状态 |
| Key 撤销或账号停用 | 新连接拒绝、旧连接终止、后台模型调用停止或取消、控制权安全清理 |
| 账号额度耗尽 | 不产生新付费模型调用；不删除 Memory / Task，不重写为成功 |
| 服务器卷或备份恢复后缺失存档引用 | 进入恢复受阻，保留事实与诊断；不空库初始化或改写玩家存档 |
| 并发连接相同账号或伪造世界 ID | 账号和活动世界边界成立，其它账号运行及记忆不受影响 |

公网验收在 Phase11.1 恢复矩阵上增加受控延迟、断开长流、回包丢失、入口重启与 worker 重启。场景由测试自有环境注入，记录输入网络条件、操作时序、真实动作、任务证据和最终状态。

## 12. 部署、观测与发布

- 构建 Linux amd64 托管服务与固定版本 worker 镜像，记录 commit、Protocol pin、镜像摘要、配置版本和兼容 Adapter 版本。现有 Windows 本地便携包继续独立构建。
- HTTPS / gRPC 域名、证书自动续期、HTTP/2 长流与私有网络均在预发布环境验证。
- 控制进程管理 worker 镜像与持久卷，使用固定参数白名单；账号输入不能形成容器命令、镜像名称、挂载路径或私有地址。
- 每个 worker 配置 CPU、内存、进程和磁盘预算；通过活跃账号、连接、回合、模型并发与上下文长度压测确定内测容量。
- 记录连接失败 code、worker 生命周期、恢复受阻、模型时延与取消、额度预留与结算、磁盘与备份状态；跨层使用请求关联 ID。
- 账号标识只在受限运维日志中使用，监控标签避免无限增长。日志与 Trace 脱敏，不记录 Key、密码、会话凭证、完整请求体或模型上游秘密。
- worker 更新按账号排空，确认退出后用相同卷启动新版本并要求 Mod 重连。数据库格式未经兼容验证时先完成备份和迁移演练，不直接降级挂载。
- 发行说明写清支持游戏、Mod / Protocol 版本、云端上传范围、额度、连接限制、数据保留与故障时游戏行为。服务不可用时客户端保留原生游戏交互。

## 13. 实施工作单元

| 单元 | 交付 | 完成条件 |
| --- | --- | --- |
| A：托管 worker 与隔离 | headless 托管入口、私有管理接口、独立卷和单写入者管理 | 两个账号使用相同游戏 / world / entity / task ID 仍无法交叉读取；终止与重启不创建第二写入者 |
| B：账号与接入网关 | 邀请、登录、网页会话、Key 发放撤销、TLS 双向长流和路由 | 未授权消息不进入 Runtime；撤销与重启验证通过；不能指定其它 worker |
| C：Stardew 远程 Mod | 连接模式、Key 设置、状态与重连、版本提示、发行包文档 | 干净客户端无需本地 Runtime 或模型 Key，通过真实公网接入 |
| D：模型与额度 | 私有模型代理、预留结算、账号和全局预算 | 并发、取消、超时与进程重启不绕过额度，不泄露上游凭据 |
| E：账号网页与偏好 | 复用任务组件、账号接入指引、Key、用量、有限偏好 | 账号切换清空旧视图；所有接口隔离；玩家无需模型配置即可游玩 |
| F：恢复与上线 | 公网故障矩阵、实机闭环、备份恢复、容量与发布演练 | 明确容量和限制后开放邀请内测；实机、自动化和部署验证分别记录 |

工作单元按依赖执行，平台模型的基础配置可供 B / C 联调；对玩家开放前 A 至 F 均须满足对应条件。每项代码完成相关回归、内部审查与 `git diff --check`，文档状态与实际验收分别维护。

## 14. 上线验收

1. 一台未启动本地 Runtime、未配置模型 Key 的干净玩家电脑，仅安装所需加载器和 WIA Mod、填写个人 WIA Key，即可在未使用 WIA 的现有游戏存档中完成真实对话；包含无法恢复的既有 WIA 引用时明确阻断并提示。
2. 两个账号并发使用相同游戏世界与角色标识，任务、记忆、偏好、回合、密钥和额度完全隔离；越权输入与旧响应验证通过。
3. 服务端进程和 worker 重启后，账号绑定、持久数据与额度账本仍成立；一个账号故障不改变其它账号数据或游戏配置。
4. 真实公网完成预约创建、保存退出、重新加载、见面和过期闭环；断网和结果不确定时按事实协调或明确暂停。
5. Key 轮换保持同一账号记忆；撤销和账号停用终止相应准入与活动连接，日志和模型请求无凭证泄露。
6. 网页区分服务、Runtime、游戏连接与世界 Ready；登录变化、worker 替换和回档不会串入旧内容。
7. 达到额度或服务容量上限后不再发起越界模型调用；客户端有可理解的提示，游戏维持原生操作。
8. 备份在隔离环境实际恢复成功；缺失 checkpoint 的场景明确阻断，恢复目标、保留期限和操作步骤已公布。
9. 内测容量来自指定服务器与所选模型的压测结果，监控、证书续期、滚动更新和故障回退均完成演练。
10. 本地模式构建和使用回归通过；公开 README、STATUS、托管使用与安装文档只标注已验证的范围。
