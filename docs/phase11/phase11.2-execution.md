## 2. 存储与架构边界

| 数据 | 权威存储 | 写入所有者 |
| --- | --- | --- |
| 账号、验证状态、管理员身份、邀请、会话、WIA Key | 控制进程卷内 `accounts.sqlite` | 账号模块 |
| 验证码、重置令牌、发送频率和审计 | 同一账号 SQLite；敏感凭据保存摘要 | 账号模块 |
| 显式偏好、模型额度与未知结果预留 | 同一账号 SQLite | 托管服务 |
| Memory、关键经历、Task、checkpoint、Trace | 各账号 Runtime 持久卷内现有存储 | 对应 Runtime |
| 游戏存档、游戏时间与真实动作结果 | 玩家游戏及 Adapter | 游戏 |

延续现有 SQLite、WAL、短事务和有界锁等待。注册、邀请兑换、一次性凭据消费和密码重置采用事务提交。SMTP 发送与密码哈希在数据库写事务外完成。

账号库增加显式 schema 版本和必要的增量迁移。迁移前备份，迁移失败保留原数据并阻止服务进入就绪状态。升级保持 `user_id`、主秘密、卷归属、偏好、额度账本及游戏数据的身份连续性。

Core 不读取账号库、邮箱或管理员身份。Protocol、游戏事实契约和现有数据归属规则保持不变。生产部署使用单机持久数据卷；同一 SQLite 文件不由多台主机通过共享文件系统并发访问。

## 3. 邮箱账号闭环

### 3.1 注册

玩家填写邀请码、邮箱、密码和邮箱验证码。普通登录继续使用邮箱与密码。

1. 请求验证码前校验邮箱格式和邀请有效性；发送请求不占用邀请码。
2. 生成六位随机验证码，将验证用途、规范化邮箱、随机挑战标识、凭据摘要、有效期、错误次数和消费状态持久化。
3. 验证码有效期 10 分钟，同邮箱与用途的发送间隔 60 秒；单个挑战最多允许 5 次错误验证。沿用认证入口预算，并增加发送入口的持久化限额。
4. SMTP 成功接受发送后，挑战才可使用。发送失败或状态未知的挑战不可兑换，页面给出重试反馈。后续重发成功使同用途旧验证码失效。
5. 最终注册在同一事务内检查并消费验证码和邀请码、创建账号并写入邮箱已验证状态。任一步失败均不产生半注册账号或单独消耗邀请。
6. 并发兑换只有一个请求成功。重复提交已完成注册时返回可理解的登录指引。

邮件正文与日志不包含密码、WIA Key 或平台模型凭据。低熵验证码使用带服务端秘密的摘要，数据库不保存可直接使用的验证码。

### 3.2 现有账号补验

旧账号的邮箱验证时间为空，原 `user_id` 和游戏数据保持有效。密码验证成功后，未验证账号进入邮箱补验流程；补验会话仅允许查询自身身份、发送或提交验证码以及退出。

邮箱补验通过后轮换网页会话并开放正常账号页面。已有 WIA Key 沿用原到期与撤销规则，新建 WIA Key 和访问管理员页面要求邮箱已验证。补验不自动重置密码、撤销既有 Key 或生成新账号。

### 3.3 找回密码

找回请求采用统一响应，避免暴露邮箱是否注册。已验证且启用的账号可以收到一次性重置链接；旧账号先通过登录后的邮箱补验流程。

- 重置令牌由密码学随机数生成，保存摘要，有效期 30 分钟；后续成功签发使旧令牌失效。
- 链接只使用部署配置中的网站 origin。令牌通过页面片段交给表单，提交时放在请求体中，访问日志不记录令牌。
- 打开页面和邮件扫描器预览不消费令牌。提交有效新密码时，在同一事务内消费令牌、替换密码、撤销网页会话与 WIA Key，并写入审计。
- 密码规则沿用当前 12–128 字符及 Argon2id 参数。成功后回到登录流程，提示原 Mod Key 已失效，需要重新生成。
- 令牌过期、已用、发送失败、数据库失败和重复提交均有明确状态。用户身份及其游戏数据保持连续。

### 3.4 邮件发送

生产邮件发送配置包括 SMTP 主机、端口、TLS 模式、发件地址及环境变量中的认证凭据。连接与发送设置有限超时，证书按标准验证。

测试使用进程内假发送器和本地测试收件端，覆盖模板、链接、成功、失败、超时和重启。生产配置缺失时明确报告邮件服务未配置；测试验证码不进入生产响应、日志或管理员页面。

管理员邮箱为 `zlci77@163.com`，它是账号登录邮箱。SMTP 发件账号、发件域名和密码单独配置。真实收件、垃圾箱分类、验证码抵达及重置邮件由用户验证。

## 4. 最小管理员后台

### 4.1 权限与入口

账号采用普通用户与管理员两种身份。管理员权限由私有 CLI 授予指定的已验证、启用账号；目标账号为 `zlci77@163.com`。权限不由首个注册者、前端参数或邮箱字符串自动获得。

管理员通过现有网站登录。后端对每个管理请求验证当前会话、账号启用状态、邮箱验证状态及管理员身份；写入请求沿用 Origin、CSRF 和审计边界。前端菜单仅控制可见入口。

### 4.2 页面与操作

| 页面 | 展示内容 | 允许操作 |
| --- | --- | --- |
| 邀请码 | 标识、创建时间、到期时间、未使用/已使用/已过期/已撤销、兑换账号 | 创建单个一次性邀请、创建后复制、撤销未使用邀请 |
| 用户 | 用户 ID、邮箱、验证状态、启用状态、注册时间 | 停用、启用 |
| 运行状态 | 用户对应 worker 的已分配/运行/未运行/恢复受阻、连接状态、最后读取时间 | 刷新只读状态 |
| 用量 | UTC 日期、已结算、未结算预留、剩余额度 | 查询 |
| 审计 | 时间、操作者、动作、目标、结果 | 查询 |

邀请默认有效期 72 小时。明文只在创建响应中显示一次，列表保留标识和状态。创建成功但未保存明文时，管理员可以撤销该邀请并创建新邀请。

停用账号会撤销会话与 Key，并按既有连接失效机制断开接入；启用只恢复账号可用性。已撤销凭据保持撤销，玩家重新登录并创建 Key。操作前展示目标账号与影响，管理员不能通过网页停用自身。

列表采用有界分页。审计不记录密码、验证码、令牌、Key 明文和模型凭据；管理员不浏览玩家的私有对话与记忆正文。首版不提供网页授予角色、删除账号、调整额度、释放未知预留、直接重启 worker 或修改数据库。

### 4.3 状态读取

管理概览只检查已存在的分配、容器和连接快照。读取路径不调用 `Workers.Ensure`，不启动、重建或初始化用户 Runtime。

没有分配、容器停止、检查失败和恢复受阻分别展示。Docker 检查失败保留最后成功时间并提示刷新，不把未知状态改写为离线或正常。

- 同表单的标签、输入框、辅助说明与按钮对齐；状态标签高度和表格操作列保持一致。
- 输入中、提交中、成功、失败、失效、无权限、无记录与读取过期状态均有对应反馈。
- 倒计时重发由服务端有效期约束，页面刷新保留合理状态。提交失败保留邮箱和其他可安全保留的输入。

- 320、390、1440 像素宽度检查窗口与中文排版。较窄屏幕的表格在容器内滚动，页面本身不横向溢出。
- 退出、账号切换与权限失效取消请求、清理明文凭据和管理数据，旧响应不回填新账号页面。

## 8. 验证矩阵与证据

### 8.1 后台与浏览器

| 场景 | 通过条件 |
| --- | --- |
| 邮箱验证 | 正确值可兑换；错误、过期、次数耗尽和旧码明确失败；重启后保留有效期与错误次数 |

游戏测试使用独立测试账号、Runtime 数据根与存档副本。测试 Mod 配置先备份，测试后恢复；正式存档、正常读取权限和既有玩家数据保持完整。当前全局 Saves 目录不作为可直接搬移或替换的测试入口。

SMAPI 诊断命令只能证明其实际执行路径。F8、原生赠送、保存与读档等 UI 行为需要可用的原生操作通道或人工操作证据。单纯编译、反射探测、fake 游戏和日志注入不能代替这些结论。

实机前核实隔离和操作通道；缺失时继续后台工作并记录受阻项。遇到异常停止测试写入并保留诊断。连接故障应保留原生游戏交互；数据恢复受阻应保留原卷并拒绝用空历史替代。

| 隔离测试存档 | 尚未核实可安全使用的测试副本和加载方式 | 真实游戏写入测试 | 执行前确认副本、配置备份及明确测试入口 |
| SMTP 与真实收件 | 配置尚未提供；用户承担真实收件验证 | 真实邮件成功结论 | 用户配置发件服务并验证收件；后台使用测试发送器 |
| 网站与网关域名 | 尚未提供 | 公网 DNS、证书与长流验收 | 用户提供域名及已配置的解析 |
| 模型与费用配置 | 正式主机的凭据、模型与预算尚未核实 | 真实模型、公网游玩及开放规模 | 用户保留私有配置，部署时验证连接并设预算 |

### 9.3 开放邀请前需要确定

1. 目标服务器、部署区域、访问方式以及网站和网关域名。实际采购与账号操作由用户处理。
2. 首批开放账号数、同时保留的 worker 数和可接受的模型日费用上限。现有示例的 3 个 worker、全局模型并发 2 仅作起测配置，邀请规模根据实测确定。
3. 异机备份位置、备份频率、可接受的数据损失时间和恢复时长。部署支持停服整卷备份，维护窗口需要与恢复目标一致。

这些是部署配置和上线条件，功能开发可以先推进。真实邮件验收由用户完成；Docker、公网、实机与恢复项目全部按实际证据记录状态。
