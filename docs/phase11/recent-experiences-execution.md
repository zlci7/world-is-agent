# 近期经历记忆执行方案

## 目标与范围

玩家完成一次真实送礼后，相关角色在关注期内的每个回合都获得这条可信经历。期间的普通聊天增长、历史摘要压缩和 Runtime 重启不改变其选取资格。超过关注期后，原始事实仍可按话题检索。

首个游戏接入为 Stardew Valley 单人模式下向普通 NPC 成功赠送物品。全部已有 NPC definitions 保持适用。拒收、原生物品交付、玩家口头自述和成功赠送分别处理。

交付包括通用经历契约、SQLite 持久化与索引、ContextProjection.RecentExperiences、Stardew 事实采集及后台验收。主动发信、电话、委托创建、服务器部署和完整聊天历史的回档分支隔离属于独立工作。

接口以[通用经历扩展契约](../../protocol/extensions/experiences-v1.md)为准；验证范围与构建材料见[后台验收记录](recent-experiences-acceptance.md)。

## 职责

| 层 | 职责 |
| --- | --- |
| Game / Adapter | 确认行为结果、知情角色、游戏时间、关注期限及当前存档内有效事实 |
| Protocol 扩展 | 传输可选、通用、结构化的经历元数据；保持现有 proto 字段与已发布协议 tag |
| Runtime Memory | 幂等持久化原始经历，维护可重建索引，按作用域、时间和有效性查询 |
| Runtime Context | 每回合自动选取有界经历，渲染并计入真实请求预算与诊断 |
| Agent | 根据事实、角色与话题决定是否提起经历及如何表达 |

Runtime 不解析 Stardew 私有 Observation.state，不按游戏 event_type 或物品名称分支，不推断赠送结果。

## 通用传输与存储

通过协商扩展 `gameagent.experiences.v1` 接入。独立经历使用现有 GameEvent / ContextFact，固定命名空间内携带版本、时钟标识、发生 tick、关注截止 tick 和优先级。Runtime 持久化后返回 EventAck，不启动模型回合、不占用 NPC 控制。

Observation.extensions 携带同一扩展的当前时钟与当前角色有效事实 ID 集合。该信息供 Runtime 校验与选取使用，不直接渲染进模型的 Observation。未接入扩展的 Adapter 沿用原有行为。

原始经历作为通用 `experience` 历史来源写入既有 SQLite。新增 `experience_index` 仅保存来源引用与选取元数据；原始事实与索引在同一事务提交。同一事实重复发送返回同一记录；相同标识对应不同内容返回冲突。

经历来源独立于普通回合摘要。近期查询通过索引读取完整事实，不受普通历史扫描窗口和摘要覆盖关系影响；长期文本检索沿用既有历史索引。

## Stardew 事实与存档

先核实当前游戏程序集中的送礼确认点，再接入只观察结果的采集逻辑。采集保持原生送礼、拒收、任务交付和物品扣除行为。

每次成功赠送生成稳定事实 ID。游戏存档保存已发生的事实 ID 与尚待 Runtime 确认的记录；断线时继续记录，重连后重送。Runtime 确认持久化后移除待同步内容，保留存档内的有效事实标识。

加载存档后，以存档中当前 NPC 的有效 ID 集合为新经历的可见性依据。回档分支上的赠送不能通过近期区块或经历检索重新进入上下文。旧的、未带有该事实归属契约的聊天历史继续保留已知分支隔离限制。

关注期限由 Adapter 使用游戏时钟计算。初始赠送关注期为三个游戏日；Runtime 只比较同一时钟域的 tick。

## 上下文与预算

每个回合取得当前观察后，在同一历史快照下读取近期经历。校验 game_id、world_id、entity_id、时钟、发生时间及有效事实集合。

ContextProjection 增加独立 RecentExperiences。BuildInput、Renderer、token 估算、ContextBuildReport 和最终请求硬门控同步接入。普通历史和摘要使用扣除近期经历及当前回合保留预算后的剩余容量。

初始上限为八条、768 个估算 tokens。排序采用优先级、发生 tick 和稳定来源顺序；超出容量时给出省略诊断，不突破总请求预算。原始事实不因退出关注区块而删除。

相同经历的原文避免在普通历史与近期区块重复展示。经历是历史事实，不能替代当前 Observation，也不能成为玩家长期偏好的推断依据。

## 工作单元

1. 通用经历持久化、扩展协商、幂等确认和有效性过滤。
2. 近期经历查询、上下文投影、预算、真实请求验证与长期检索。
3. Stardew 赠送采集、存档记录、离线待同步和原生交互兼容。
4. 跨仓库后台组合验收、构建、公开事实源及验收记录。

每个工作单元完成相关测试、直接回归、内部 CR 与 git diff --check 后继续。测试使用独立数据根与临时目标，不启动或激活游戏，不改写玩家正式存档、Key、Memory 或 Task。

## 验收条件

| 场景 | 通过条件 |
| --- | --- |
| 昨日赠送、今日问候 | Provider 实际接收的请求包含正确物品、角色、时间及来源，无需本轮关键词 |
| 大量对话与摘要压缩 | 普通摘要省略礼物时，关注期内的原始经历仍进入请求 |
| 重启 | 重新打开 SQLite、重建 Loop 后仍选中同一事实 |
| 作用域 | 其他 NPC、世界与游戏看不到该私有经历 |
| 关注期结束 | 退出自动区块，相关提问仍可检索原始记录 |
| 回档 | 当前存档有效集合以外的新经历不进入近期区块或经历检索 |
| 幂等与离线 | 重送不重复写入；未确认记录跟随存档，重新连接后继续同步 |
| 游戏语义 | 接受赠送产生事实；拒收与原生物品交付不产生赠送成功事实 |
| 通用性 | 两种 fake 游戏与不同事件名称通过相同 Core 测试，无 Stardew 分支 |
| 预算与兼容 | 近期经历计入最终请求；旧 Adapter、Task、历史检索、参数纠错与中文前端回归通过 |

后台测试与游戏程序集探测证明各自执行过的路径。实际送礼钩子与游戏内表现需要独立实机证据；没有该证据时，验收记录明确保留实机边界。
