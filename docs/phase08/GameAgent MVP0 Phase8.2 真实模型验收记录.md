## 3. 正式 Server 进程

验收程序构建并启动正式 `runtime/cmd/server` 可执行文件，通过受控 gRPC Adapter 交互，使用仅监听 `127.0.0.1` 的测试代理转发原始请求至 DeepSeek 官方 API。压缩触发配置为请求 16000、承载消息 6000、近期尾部目标 1000 tokens；摘要 2048 tokens / 10 秒，决策 8 秒，Provider 思考模式保持原样。

正式 server 配合本地 HTTP fixture 的三个进程验证通过。真实 DeepSeek 运行的 PID 为 37936：压缩阶段约 10 秒失败，未发布摘要；后续决策约 2255ms 完成，Turn 约 12.3 秒完成，终态历史已提交。

该真实运行未通过压缩条件，后续回档和追时进程没有执行。不能将本地 fixture 的三进程通过结果称为正式 server 配合真实模型的完整通过。

证据目录为 `server-real/real-50456-1315704922/compact-37936/`，包含摘要请求、最终决策 HTTP 请求、数据库来源 ID 和安全 trace；`evidence.json` 的状态为 `failed`。

## 4. 准确性复核

独立复审逐项核对了来源与最终摘要。生产样本 50880 保留了以下区别：

- 玩家不喜欢雨天，另一位证人喜欢雨天。
- 玩家要求口令 7319 保密。
- 玩家选择蓝色盒子，选择事件没有被改写成发言。
- 玩家声称包裹已送达；witness 的模型意图是递送，游戏回执确认递送失败、实际未送达。
- Turn `completed` 与动作成功分别表达。

该样本准确性通过，不代表所有后续摘要均可自动证明准确。覆盖指纹和事务校验保证来源一致性，不能判断模型正文是否发生语义反转。

## 5. 延迟与准确性风险

同一模型与时限的此前重复验收中，出现了摘要 10 秒超时和决策 8 秒超时。摘要失败时没有推进覆盖，Turn 按现有降级逻辑处理。成功样本不抵消这些延迟记录；当前未修改生产时限。

仅在测试子进程关闭摘要思考的对照样本中，摘要约 1.8–2.2 秒完成，但样本 54296 将“口令7319不能告诉旁人”写成“可以告知旁人”。独立复审确认这是否定反转，该摘要准确性不通过。

该错误摘要仍能完成持久化与恢复，因此流程测试通过不能替代准确性验收。生产请求没有启用这项诊断覆盖。证据为 `final-diagnostic/compact-disabled-thinking-10s-54296.json` 与 `catchup-disabled-thinking-10s-19192.json`。
