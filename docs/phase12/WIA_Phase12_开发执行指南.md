# World Is Agent Phase12 开发执行指南

状态：开发组织与验收合同，功能完成情况以[开发状态](WIA_Phase12_开发状态.md)中的实际证据为准。

## 1. 任务入口

依次阅读仓库 [AGENTS.md](../../AGENTS.md)、[产品说明](WIA_产品说明_v1.0.md)、[技术方案](WIA_Phase12_技术方案_v1.0.md)和[开发状态](WIA_Phase12_开发状态.md)。产品说明决定体验与范围，技术方案决定核心合同，本指南决定执行与验收节奏，状态表记录已经完成的结果。

本任务将 WIA 开发为独立的 AI 叙事角色扮演产品。代码可按该目标重构、替换或删除，模型、身份、SQLite 与执行基础设施按实际适用性复用。正式产品使用一个叙事后端入口与一套玩家界面，Adapter 兼容不构成设计或验收要求。历史说明不作为当前功能已经实现的证据。

当前工作范围为 world-is-agent 仓库。每个独立小工作单元完成并通过相关检查后，已授权执行一次本地 git commit，无需逐次询问。不得将代码调整授权解释为删除用户存档、修改文件访问权限、操作其他仓库、发布到生产环境或执行 git push 的授权。模型密钥、用户存档与本机配置不进入提交或交付附件。

## 2. 执行与人工验收节奏

一个大阶段是一次完整交付单位。开发会话自行拆分内部工作、选择常规实现细节、修改代码、运行测试、检查结果并修复问题，不为文件、接口、小模块或每个内部步骤请求用户确认。

Git 提交以独立小工作单元为粒度：一个功能、修复或完整文档改动及其必要测试组成一次提交。提交前完成适用的测试、直接受影响的回归、代码自查和 git diff --check，并检查暂存区仅含本单元内容。提交信息说明实际功能或行为，不使用无法解释的“阶段完成”标签。修复未完成或必要检查失败时先解决问题，不通过提交次数代替完成质量。

每次本地提交后继续当前大阶段，无需等待用户验收；阶段交付时提供相关提交及验证结果。不得擅自推送、重写既有历史或混入用户无关的未提交修改。

默认一次任务完成用户指定的大阶段；未指定时，从状态表中第一个未完成阶段开始。阶段内持续执行，完成整个阶段后一次性交付可运行版本、验证结果和简短体验路径。用户在大阶段边界验收，不参与日常代码检查。

用户明确授权连续完成多个阶段时，各阶段通过工程验证后可以继续；分别保留阶段验收结果，不把“尚未人工体验”当作后续开发的自动阻塞，也不把它标成用户已验收。用户要求只开发某阶段时不得扩大到后续阶段。

只在确实缺少无法推断的信息时提问，例如没有可用模型凭据、没有目标测试环境，或新需求改变已确认产品规则。提问应说明具体缺项，并继续完成不依赖该答案的工作。既有凭据可用时直接使用受控配置，不再次询问已授权的本产品模型测试；不得擅自购买套餐、充值或更改服务额度。

已确认的剧本模式、存档语义、NPC 分工和容错原则直接执行，不反复发起架构评审。技术细节根据现有方案与工程判断落地，只有改变用户可见规则或增加产品范围才需要用户决定。

## 3. 全程保留的核心合同

- 身份采用 game_id（剧本）、world_id（持续游玩的存档）、entity_id（NPC 实例）和 definition_id（初始模板），user_id 独立负责所有权。
- 每个世界一个数据库。正常游玩更新当前世界；另存复制当前完整进度并创建新 world_id；读取 B 后继续更新 B，不隐式创建副本，不恢复未保存的旧进度。
- 同一后端同一账户共享活动世界；显式激活才切换，普通读取不切换，重复激活当前世界不取消任务；旧设备按活动版本拒绝过期写入。
- 场景主 Agent 组织世界、环境、路人与叙述；重要 NPC 独立决定回应，程序管理感知来源、状态与提交。
- 开放型和流程型都允许世界剧情。玩家自由参与开放型事件；剧情按游戏内时间和条件发展，离线与界面操作不推进世界。
- 接受少量可纠正的叙事幻觉，不固定增加裁判或逐句语义证明；数据隔离、版本与事务正确性须由程序保证。
- 从首个可玩版本建立世界所有权、独立感知、回合事务、取消与重复请求处理，不在长期无作用域的聊天实现上补齐这些边界。
- 一个正式入口、一套玩家前端、模块化单体；不建设跨产品通用框架、微服务或任意插件系统。

## 4. 大阶段 M1：核心游玩与可靠存档

### 交付结果

本机可直接运行一个小型调查冒险，玩家与至少两名重要 NPC 及背景路人互动。各 NPC 读取独立的感知与个人来源，形成简明个人状态；正文、事件及人物经历持久化到当前世界。玩家可以关闭后继续、另存当前进度及读取已有存档。

包含正式叙事入口、基础模型配置、剧本/世界/人物身份、初始场景、主 Agent 与 NPC 协调、受限上下文、世界库、基础检索、玩家正文与输入界面、生成状态、取消、失败重试和存档列表。模型接入使用真实 Provider，fake 仅用于可重复测试。

世界时间、剧情版本和内容版本从此阶段进入数据合同；完整剧情推进和长期整理在 M2 完成。账户作用域从此阶段存在，本机可使用内部 local owner；面向服务器的真实登录在 M4 完成。

### 首个工作单元与复用边界

首条可玩样本采用两名重要 NPC 与若干路人：玩家私下告知老板，佣兵只获知交谈迹象；老板公开回应后，佣兵在下一阶段反应；整轮提交后另存为 B，继续 A，再读取 B。另设同轮中途进入/离开的变体，检查前后场景版本下的信息范围。样本通过不等于 M1 已完成。

执行前以实际源码核对复用点，并直接落实相关接口和测试：

- TextGenerator 可复用；ValidateTextJSON 的语法检查之外补齐重复键、关键字段和业务引用校验。正式入口对未配置模型明确报错，不能因旧工厂默认 Fake 而假报就绪。
- WorldStore 统一拥有回合事务。记忆、事件、正文和完成态使用同一事务绑定接口，不顺序调用会各自提交的旧 Store API 来冒充原子完成。
- 旧维护队列可以替换尚未执行的 maintenance；必须完成的另存与重建任务需要明确状态和恢复语义，不能直接交给可静默替换的队列。取消、排空等实现按适用性复用。
- AppHost 使用用户作用域、不可变模型档案和运行快照，不复用会全局退役其他用户实例的配置切换流程。
- 事件、感知及进出场顺序绑定来源快照；上下文从有效剧情来源读取，未完成输入只作展示和当前重试用途。
- 必需重建未完成时在复制冻结前返回 memory_rebuilding，取得预约后再次核对；不持有重建所需的发布禁令等待它完成。M1 用受控重建状态测试，M2 接入真实重建任务后复验。

### 开发会话必须验证

自动验证核心回合、私聊与旁观请求内容、沉默经历保存、阶段因果、幂等、原子提交、取消竞争、刷新重启、存档复制/读取、失败复制恢复和跨世界隔离。使用真实模型完成短篇连续游玩与存读档往返，检查玩家界面可操作。

首批回归包含：同轮中途进入/离开；失败的“告诉佣兵秘密”不出现在后续个人记忆、正文尾部、回顾和建议输入；同账户两客户端显式切换、只读刷新、重复激活及过期请求；另存与重建竞争；未配置模型和非法结构化输出。M1 未交付的摘要/建议消费者在 M2/M3 补齐后继续覆盖，不能把尚未实现的消费者标为已验证。

M1 就测量普通对话、私聊和插话三类真实模型路径，记录样本数、总等待、各步骤耗时、失败率、并行和格式修复情况。300 秒仅作执行保护，不作为体验达标线；不以调用并行或少量成功样本推断速度足够。阶段报告如实呈现等待体验和可定位的耗时，不要求用户代为采集性能数据。

更新构建与启动路径，使交付应用可以在没有 Adapter 和游戏运行时的情况下独立游玩。旧链路按依赖替换退出；不以仅创建新目录作为完成。

### 用户仅需体验

1. 打开准备好的示例，与两名人物交谈并尝试一次私聊，判断整体是否像可玩的故事。
2. 另存为 B，继续 A，再读取 B 继续；退出重开，确认看到的是 B 的最新进度。
3. 反馈人物和叙述是否基本自然、等待及存档操作是否清楚。

实现故障注入、查数据库、查看请求隔离和测试代码由开发会话完成，不交给用户。

## 5. 大阶段 M2：世界剧情与长期记忆

### 交付结果

同一小型背景提供开放型与流程型。世界事件有条件、有游戏内时间、有干预后果；玩家不参加时事件仍按条件演进。流程型有关键节点和结束条件。离场重要人物按事件需要参与，获知消息仍有来源。

自动维护个人与玩家回顾，保留近期尾部，检索旧事，延续信念、关系与约定。提供可用的来源检查和统一纠正入口，完成失效、重建与恢复。存档包含全部时间、剧情和记忆状态。

### 开发会话必须验证

覆盖长期来源、摘要覆盖与失效、条件变化、离线不推进、事件顺序、节点幂等、场外消息传播、结束条件、纠正作用域和存读档一致性。将另存/重建竞争接入实际重建任务回归，确认失败输入不能通过摘要、检索或剧情条件重新进入历史。

对开放/流程两种配置分别运行真实模型情境：参与、干预、不参加、旧约定重提、离场重返、纠正后继续。按技术方案积累长程质量证据，少量语义偏差按影响程度记录，不执行零幻觉验收。

### 用户仅需体验

1. 开放版选择参加或忽略一条事件，观察是否有合理发展且不被强迫接任务。
2. 流程版沿不同选择推进，感受主线和人物回应是否成立。
3. 查看旧事或纠正一条记录后继续，判断故事是否能够接续。

## 6. 大阶段 M3：完整玩家工作台

### 交付结果

形成普通玩家无需组装配置的完整使用路径：剧本/主角/人物管理、默认行动建议与自由输入、回顾与纠正、路人保留为角色、基础外观与响应式界面。

完成手动编辑、TXT/Markdown、自有内容包与约定的 CCV2 JSON 文本导入；提供映射报告、剧情文本整理与作者确认。初始知识、作者隐情和玩家视图正确分开，模板与已有世界的修改各有明确语义。

### 开发会话必须验证

通过界面实际完成创建、导入、预览、开局、编辑、保留人物、建议使用/关闭、纠正和导出往返。覆盖未知字段、无效文件、过期建议、正在输入时迟到响应、隐情视图与附件引用；补齐失败输入不进入建议及玩家回顾的端到端测试。修复验证中发现的问题后再交付。

此阶段完成至少三个题材的测试内容以及技术方案要求的连续交互与关键情境重复测试，记录真实模型质量、等待时间和调用量。无需用户亲自重复这些测试。

### 用户仅需体验

1. 从首页开始新故事，判断是否能自然发现所需操作，无需理解技术参数。
2. 自由输入或使用建议，查看回顾与人物信息。
3. 体验一次导入或创建，以及把路人保留为角色，反馈流程是否清楚。

## 7. 大阶段 M4：桌面、服务器与完整交付

### 交付结果

交付可安装/运行的 Windows 桌面包、本机浏览器使用方式和 Linux 自托管服务器版本。桌面管理自己的后端进程；服务器提供真实用户、授权模型档案和手机浏览器可用的体验。

完成安装启动、会话安全、用户与凭据隔离、出站模型连接策略、备份恢复、附件恢复及发布构建。正式产品构建与启动不包含 Adapter 运行前提，公开说明只描述实际通过验证的能力。

### 开发会话必须验证

完成实际 Windows 启动退出、进程复用、Linux 部署测试、多用户隔离、移动视口与可用设备上的交互，以及备份恢复演练。实际验证电脑在 A 生成、同账户手机激活 B 后的切换提示和旧请求拒绝，同时确认不同用户互不影响。仅在用户已授权的环境执行部署，不擅自发布生产服务。

核对所有自动化验收项及质量评估证据，执行受影响回归、前后端构建和类型检查。环境不具备时明确标记待验证，不能用打包成功冒充实机运行成功。

### 用户仅需体验

1. 像普通玩家一样启动桌面应用并继续已有存档。
2. 如有可用部署，在电脑或手机登录并接续同一后端上的故事。
3. 对完整产品是否顺畅、可理解、愿意持续游玩作最终验收。

## 8. 自动验证责任与完成判定

技术方案的 A 项由开发会话验证，Q 项由开发会话先做真实模型和界面评估；用户只做每阶段列出的体验验收。所有关键程序测试通过后才标记工程验证完成，不将失败测试留作用户检查清单。

| 阶段 | 基础合同主责验收项 |
| --- | --- |
| M1 | A01–A13、A22–A28、A32、A40–A48、A61–A67 |
| M2 | A14–A19、A51–A60 |
| M3 | A20–A21、A35、A39 |
| M4 | A29–A31、A33–A34、A36–A38、A49–A50 |

该表表示各项基础合同的主责阶段，不表示早期可以省略已经实现功能的检查，也不把后续消费者提前记为通过。M1 的本地所有权、删除和隔离须验证；A12/A65 的摘要与建议消费者在 M2/M3 补齐，A64 的真实重建竞争在 M2 复验，A62/A63 的账户多设备实机在 M4 复验。阶段报告逐项说明已覆盖范围和待验证范围，完整功能集齐后再将组合验收项标为全部通过。

有真实模型或设备依赖却暂时无法运行时，记录“待验证”及确切缺项，继续独立工作。完成实现、通过自动测试、通过真实环境验证、用户体验认可分别记录。用户未回复不代表认可；测试没有运行不代表通过。

禁止以减少既定范围、删除有价值的失败测试、仅使用 fake 或把错误归入幻觉的方式宣告完成。可接受的叙事偏差不触发无限调优；聚焦高频、严重或破坏持续游玩的缺陷。

## 9. 每阶段交付与新会话接续

每个阶段结束时更新开发状态，并在 `docs/phase12/acceptance/M1.md` 等对应阶段文件中记录最终验证结果。仅在阶段实际有结果时创建报告，不预填成功。报告包含：

- 可运行入口、构建/启动命令和必要模型配置说明，不包含秘密。
- 本阶段实际交付的功能及小工作单元对应的本地提交，必要时说明尚未提交的工作区状态。
- 实际执行的测试、结果与证据位置，区分自动测试、真实模型、界面和实机验证。
- 已知限制及其对游玩的影响，不复述尝试过程或废弃方案。
- 本阶段用户体验步骤，以及工程验证状态和人工验收状态。

开发状态保持简洁，只记录当前成果、当前任务、已知阻塞及验证证据。新会话先检查真实代码和状态，再从未完成工作继续；不能仅凭历史聊天声称某阶段完成，也不重复推翻已经确认的产品规则。

会话因上下文或外部原因需要交接时，保存接续所需状态。该记录不意味着阶段已完成，也不将接续工作转为用户逐步检查。
