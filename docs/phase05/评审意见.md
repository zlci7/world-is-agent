# 0. 归档说明

Phase5 已于 2026-08-27 验收。当前实现口径如下：

```text
- settle 是 AgentTurn control，不是 Environment Tool。
- 真实 OpenAI / DeepSeek provider 使用 no-tool final response 表达 settle。
- __gameagent_settle 只保留 provider parser 兼容路径，不进入 Tool Registry / Scheduler / Adapter。
- Phase5 不实现 finish_turn Runtime Tool，也不要求真实模型调用未声明 tool。
```

因此，本文后续出现的 `finish_turn`、Runtime reserved tool name、Runtime Tool collision 等内容，按“早期方案评审记录”阅读；当前设计以主方案的验收快照和 R15 为准。

## A（P1，有效）：max_steps=3 与 Phase4 默认 TurnTimeout=15s 冲突

```text
scripted provider 因为瞬时返回，会掩盖这个问题。
```

处理：

```text
已补入主方案 §3.9 / Step 1 / Step 3 / 测试矩阵 / 验收标准 / R5。

裁决：
    Phase5 默认 max_steps = 3。
    Phase5 默认 turn_timeout_ms = 45000。
    TurnTimeout 仍优先于 max_steps。
    max_steps_exceeded 测试必须给足 TurnTimeout。
    另写 delayed provider 测试，证明短 TurnTimeout 会抢占 step budget。
```

## D（P1，有效）：ActionResult non-SUCCEEDED 不能全部进入下一步修正

问题：

```text
Protocol 中 ActionStatus 包含：
    PENDING
    ACCEPTED
    RUNNING

这些是非终态状态。
Phase5 明确不做 async Action，
因此不能在前一个 Action 尚未终态时发起下一步。
```

处理：

```text
已补入主方案 §3.6 / Step 4 / 测试矩阵 / 验收标准。

裁决：
    SUCCEEDED -> success
    REJECTED -> Phase5 P0 可修正路径
    FAILED / CANCELLED / INTERRUPTED -> terminal failure feedback，可进入 CurrentTurnSteps
    PENDING / ACCEPTED / RUNNING / UNSPECIFIED -> turn_failed(stage=action, reason=non_terminal_action_status)
```

## E（P2，部分有效）：默认 max_steps=3 不覆盖 4-step 恢复路径

问题：

```text
max_steps=3 可以覆盖：
    speak -> emote -> finish_turn
    REJECTED -> corrected -> finish_turn

但不能覆盖：
    successful action -> failed action -> corrected action -> finish_turn
```

处理：

```text
已补入主方案 §3.9 / 测试矩阵 / R6。

裁决：
    不把默认 max_steps 提到 4。
    该路径接近局部 recovery / side-effect compensation，不作为 Phase5 P0。
    需要时由调用方显式配置 max_steps >= 4，并同步提高 TurnTimeout。
```

## F（P2，有效）：Runtime Tool 冲突规则需要固定语义

## G（P3，有效，已纳入）：Registry.Available() 顺序必须稳定
