# WIA RimWorld Adapter

Connects RimWorld to a local [World Is Agent](../../README.md) Runtime.

```text
Requires      WIA Protocol v1alpha2
Tested against protocol-v1alpha2.0
Game          RimWorld 1.6.4871 (Unity 2022.3.35f1, Mono 6.13)
```

This is the second real adapter for WIA. Its current scope is **dialogue only**: a colonist can talk
to the player, and the reply is generated by the Runtime's normal event → observation → context →
model → capability chain. It does not move pawns, take over RimWorld's AI, or react to world events
on its own.

## Requirements

- RimWorld 1.6 with the `Human` def unchanged for the colonist gizmo to appear.
- A WIA Runtime listening on `127.0.0.1:50051` (the Runtime's default adapter port). Start it before
  or after the game; the adapter reconnects while the Runtime is unavailable.

## Build

No game installation is required. The project compiles against reference assemblies published with
Ludeon's permission (`Krafs.Rimworld.Ref`), so no game binary is redistributed and CI needs no game.

```powershell
dotnet build WiaRimWorld.csproj
```

The protocol is located through `WIA_PROTOCOL_DIR`, with a repository-relative fallback for local
development:

```powershell
dotnet build WiaRimWorld.csproj -p:WIA_PROTOCOL_DIR=<path to protocol>
```

To verify that the adapter builds with no game and outside the repository layout:

```powershell
adapters/rimworld/tests/check-standalone-build.ps1
```

## Install

```powershell
scripts/install-rimworld-adapter.ps1 -GamePath "<RimWorld install>"
```

The game path can also come from `WIA_RIMWORLD_GAME_PATH`. Then enable **World Is Agent (RimWorld)**
in RimWorld's mod list.

The installed layout is not a plain copy of the build output:

```text
<Game>\Mods\WiaRimWorld\
  About\About.xml
  Assemblies\   WiaRimWorld.dll + its managed dependencies
  Native\       grpc_csharp_ext.dll
```

Two rules are enforced by the install script because RimWorld's loader requires them:

1. **The native library must not live in `Assemblies/`.** RimWorld hands every `*.dll` in that folder
   to `Assembly.LoadFrom`; a native image throws `BadImageFormatException`, and because managed
   assemblies load in filename order, that failure can stop the adapter assembly from loading at all.
   The symptom is a game that runs normally with a silently inactive mod.
2. **The native library must be named exactly `grpc_csharp_ext.dll`.** That is the name
   `Grpc.Core`'s `DllImport` asks for; Windows `LoadLibrary` does not match an already-loaded module
   by a different base name. The adapter pre-loads it by absolute path at startup.

## Transport

The adapter talks to the Runtime with `Grpc.Core` (the native C-core implementation) over an
unencrypted loopback HTTP/2 stream.

This is not a preference. RimWorld runs on Unity's Mono, whose BCL has no HTTP/2 implementation:
`System.Net.Http.SocketsHttpHandler` does not exist and the assembly contains no HTTP/2 identifiers
at all. `grpc-dotnet` therefore cannot work in this process, and gRPC-Web is not an option because
the adapter protocol is a single bidirectional stream. `Grpc.Core` bypasses the BCL HTTP stack
entirely, at the cost of carrying a native library and depending on an upstream that is in
maintenance mode. That debt belongs to this adapter, not to the Runtime or the protocol.

## Status

Early. The adapter currently completes the handshake (hello, environment ready, capability
declaration) and publishes no capabilities yet. Identity, observation and the dialogue capability
arrive in later stages; see
